## 2. 项目是什么

FastGithub 的 Go 重写：本地 DNS 净化 + 多 IP 竞速 + 本地 CA 中间人，解决 `github.com` 打不开 / clone 失败。**不是翻墙工具**。

两种工作方式：

- **显式代理**（全平台）：`127.0.0.1:38457`，CONNECT 命中域名规则时 MITM，未命中盲隧道；根路径返回 PAC。
- **透明拦截**（仅 Windows，WinDivert）：劫持 UDP 53 与 TCP 443/80/22/9418，浏览器无需配置代理。

域名规则只决定“哪些域名被接管/优化”，不决定“是否走代理”。当前 55 条规则来自原版 9 份 `appsettings.*.json`，在 `conf.d/`。

### 5.4 透明拦截（前台运行）

```powershell
.\fastgithub.exe run --path .\fastgithub.toml
```

预期日志：

- `代理已启动: 127.0.0.1:38457`
- `UI: http://127.0.0.1:38470/`
- `透明拦截已启用: map[...]`（map 是“实际端口 → 偏好端口”）

逐项验证：

1. **DNS 劫持**：`nslookup github.com` 与 `nslookup github.com 8.8.8.8` 都应返回 `127.0.0.1`；未命中域名（如 `nslookup baidu.com`）返回真实地址。
2. **浏览器**：不配置任何代理，直接打开 `https://github.com`；证书颁发者应为 `FastGithub`，页面正常。
3. **未命中域名**：打开 `https://www.baidu.com`，应正常（盲隧道），UI 日志里是 `CONNECT`。
4. **UI**：打开 `http://127.0.0.1:38470/`，确认域名命中数、请求日志、流量、证书状态、系统代理卡片（Windows 上应显示“不可用”，这是预期）。
5. **SSH**：`ssh -T git@github.com` 应返回 GitHub 的认证提示（22 端口被透明转发到 `github.com:22`）。
6. **Git 协议**：`git ls-remote git://github.com/octocat/Hello-World.git`（9418 转发）。
7. **端口顺延**：先占用 443（例如临时起一个监听），重启程序，日志应显示实际端口不是 443，浏览器仍能访问 GitHub（WinDivert 重映射生效）。
8. **IPv6**：`nslookup -type=AAAA github.com` 应返回 NODATA（若 `::1` 监听失败）或 `::1`；客户端应能回退 IPv4。
9. **退出**：Ctrl+C 后端口释放，WinDivert 句柄关闭，无残留进程。

已知限制（验收时不要当 bug）：

- QUIC/HTTP3 走 UDP 443，不经过 TCP 拦截；Chrome/Edge 可能先尝试 QUIC 再回落。可在浏览器禁用 QUIC 对比。
- SSH/Git 透明入口固定转发 `github.com:22/9418`（与原版一致）。
- UI 的“切换拦截”按钮仍是 501，启停请用 `intercept.mode` 配置。

### 5.6 服务安装

```powershell

sc query fastgithub
.\fastgithub.exe start
.\fastgithub.exe stop
.\fastgithub.exe uninstall
```

重点检查：

1. `sc query fastgithub` 状态从 `STOPPED` → `RUNNING`。
2. 服务以 `run --path <exe目录>\fastgithub.toml` 启动；`run` 会切换到配置目录。
3. `cacert/`、`logs/`、`ui.token` 应生成在 **exe 所在目录**，不是 `C:\Windows\System32`。
4. 服务运行期间 UI 可访问，透明拦截生效（浏览器无需代理）。
5. `stop` 能在 10 秒内停止；`uninstall` 后服务消失。
6. exe 路径含空格时也要验证（`serviceCommand` 已加引号）。

## 6. 已知问题与技术债（按优先级）

### P1：DNS 源只取第一个成功结果

`internal/resolver/resolve.go` 的 `lookupType` 在第一个成功源后立即返回，候选 IP 可能只有一个。macOS 实测 `github.com` 被解析到 `20.205.243.166` 时会间歇性 TCP 超时，而 `140.82.112.3` 等地址可用。

建议：把各源（DoH + fallback）的 A/AAAA 结果**合并去重**后再竞速；或在 `dialFirst` 全部失败时强制重新解析（绕过正缓存）。改动要有单测，避免把慢源拖进总预算。

### P2：`/api/intercept` 仍是 501

运行时启停透明拦截未实现。当前只能改 `intercept.mode` 后重启。实现时需要处理 WinDivert 句柄的并发启停与端口占用。

### P2：`server.singleton` 解析但未生效

没有单实例锁。Windows 上服务与手工 `run` 同时启动会争抢 443/80/22/9418 和 WinDivert 句柄（端口会顺延，但透明拦截会重复）。建议用命名互斥量（Windows）或文件锁（其他平台）。

### P3：`log.level` 解析但未使用

目前没有分级日志，所有 `log.Printf` 都会输出。

### P3：系统代理只支持 macOS

`internal/sysproxy` 在 Windows/Linux 返回 `ErrUnsupported`，UI 显示“不可用”。Windows 有透明拦截，不需要系统代理；如果以后要支持，需写 WinINET 注册表 + `InternetSetOption` 刷新。

### P3：macOS 系统代理在异常退出时不会恢复

只有收到 SIGINT/SIGTERM 才会自动关闭；崩溃或 `kill -9` 会留下指向 `127.0.0.1:38457` 的代理。Windows 不涉及。

### P3：CI 与基准

- `.github/workflows/ci.yml` 在 Gitee 不生效；Gitee 侧需要自建流水线或本地跑 `scripts/ci.sh`。
- 设计文档 §13 提到的并发/吞吐基准尚未补。
